# v0.0.0-rc.11 — Products, reviewed tools and Agents

This prerelease covers changes since `v0.0.0-rc.10` at
`2811945e83c85c3c87ceb6b0108e2d033bba77f6`. Prepared on 27 November 2026 for
`the-factory-forge/forge-registry`. The annotated tag identifies the release
commit. The reviewed application source is
`b80f3da4dd12f369a0249a7fc09530b404e34cfd`. No separately uploaded assets.

## Features

- Products adds staff management, a public catalog, categories and subcategories.
- MCP and WebMCP expose reviewed plugin tools. Agents improves chat navigation,
  model settings and model context.
- Blogs resolves published articles by ID or slug. Employees can toggle profile
  visibility from the directory. Menus simplifies publication and label management.
- The showroom gates analytics behind cookie consent, generates sitemap and robots
  routes, and links blog categories from the preview sidebar.
- Shared UI styles and showroom controls are refined.

## Fixes

- Agents preserves MCP connection lifetime and refreshes affected WebMCP data.
  It supports OpenAI Responses and history deletion, restores chat scrolling,
  prepares test-ticket proposals and derives model encryption from a host secret.
- Auth clarifies destructive account actions. Customers simplifies action feedback.
  Drive clarifies file actions and recovery dialogs.
- Projects simplifies directory headings. Reservations distinguishes cancellation
  from archive actions. Support aligns ticket toolbars and dialog actions.
- The showroom adapts preview sizing and blog simulation controls, moves language
  switching into plugin sidebars and previews both agent connection settings.

## Integration and migrations

1. Pin the complete `@forge` namespace to the verified release SHA. Install only
   the desired items and their dependencies in a disposable host before reviewing
   overwrites. Preserve host routing, translations, authorization and theme tokens.
   Use Node types for server companions and include the required component styles.
2. Products storage is new in this release. Compose its product, category and
   assignment tables with the shared plugin lock table, then generate and review
   the host migration. Existing Products installations from unreleased source
   must compare their own schema, including translations, slug and media defaults.
   The host owns product image storage, authorization and cleanup.
   See [Products](https://github.com/the-factory-forge/forge-registry/blob/b80f3da4dd12f369a0249a7fc09530b404e34cfd/docs/products.md).
3. Adopt Agents, its runtime and the selected connectors together. MCP requires
   host authentication and grants; WebMCP requires the signed-in browser context.
   Writes retain explicit review. Follow [Agents](https://github.com/the-factory-forge/forge-registry/blob/b80f3da4dd12f369a0249a7fc09530b404e34cfd/docs/agents.md) and [WebMCP](https://github.com/the-factory-forge/forge-registry/blob/b80f3da4dd12f369a0249a7fc09530b404e34cfd/docs/webmcp.md).
4. Keep model-encryption secrets stable. When switching an existing separate key
   to the derived host key, re-enter the provider key or migrate its ciphertext.
   Removing the old variable alone does not convert stored credentials.
   No existing-plugin database migration is introduced by RC11.
5. The central consumer inventory was reviewed to identify adoption follow-ups.
   Publication updates no customer source, credentials, database or deployment.
   Unrecorded and uninspected consumers remain separate follow-up work.
