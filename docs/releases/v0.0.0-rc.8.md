# v0.0.0-rc.8 — Agents plugin

**Agents is available as optional source; the host supplies its AI runtime.**
Staff can select an operation, send the first message to start a private saved
chat, and approve each proposed write separately.

## Agents source and behavior

New Agents items are `agents`, `agents-server`, `agents-blogs-server`,
`agents-employees-server`, `agents-customers-server`, `agents-projects-server`,
`agents-drive-server`, `agents-menus-server` and `agents-reservations-server`.
Installing Agents alone does not install every business plugin.

- Operation cards use the plugin's title, description and icon. The first Send
  creates the chat for the selected operation. New conversation opens a draft.
- Private history spans accessible operations when none is selected, sorts recent
  chats first and restores a chat's own operation when opened. Hosts own URL state.
- Replies stream, support Stop and retry, and preserve drafts through failures.
  File selection stages private attachments and reuses existing image crops.
- The server validates model tool calls with Zod, runs authorized reads directly,
  and stores each mutation's payload and service-derived preview before approval.
  Fresh permission and preview checks precede execution; repeated approval cannot
  repeat a write. Uncertain outcomes require trusted reconciliation.
- Completed actions can link to the created record through a host-supplied
  `resultHref` callback. Hosts can register trusted custom operations with an
  explicit tool allowlist. The showroom uses a deterministic mock.

The shared plugin-icon map also changes `intranet-sidebar`; `intranet-shell` is
its reverse dependent. No existing business plugin gains an Agents dependency.
The registry package manifest and lockfile gain no application dependencies;
new item dependencies are declared in the registry manifest.

Across RC6 to RC8, the other new items are `customers-bexio`,
`customers-bexio-server` and `projects-drive`. Changed existing items are `auth`,
`blogs`, `blogs-storage`, `customers`, `employees`, `intranet-sidebar`, `lightbox`,
`menus`, `projects` and `reservations`. Additional reverse dependents are
`customers-storage`, `employees-server`, `intranet-shell`, `menus-storage`,
`projects-storage` and `reservations-storage`. No item is removed.

## Required host integration and migrations

Follow the [Agents integration guide](../agents.md). Supply fresh staff sessions,
operation authorization, an authenticated transport, the server-side model runtime
and credentials, and private storage under `<SITE_NAME>/agents/`. Supply actual
record routes through `resultHref`; the showroom links to its sample record.

Compose the exported `agentsConversations` and `agentsAttachments` tables into
the host's Drizzle schema. **Generate and review an additive PostgreSQL migration
in the host.** Registry installation applies no SQL. Existing business plugins
need no new schema simply because Agents is available.

Reuse the existing domain services, version checks, deletion previews and media
validation. Configure invitation and notification adapters deliberately. Verify
reconciliation and retryable object cleanup before deployment. RC5/RC7 migration
requirements remain relevant to older source installations.

## Adoption and limits

Pin the entire `@forge` namespace to the tag's verified full SHA, then install
selected items in a disposable host before reviewing overwrites and deployment.
Source tags do not pin unversioned npm dependencies. Hosts retain responsibility
for migrations, their real provider, quotas, S3 privacy/lifecycle rules and domain
adapters. There is no workflow builder, scheduler, background runner, OCR or
indexing. History currently shows the latest 100 chats per accessible operation;
older chats remain reachable by their direct URL.
