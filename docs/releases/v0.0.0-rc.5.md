  handwritten runtime SQL and distributed creation scripts. Persistent row locks,
  migration-journal checks and Blog projection preflight coordinate writes.
  New Customers and Projects companions provide bounded, authorized directories,
  transaction-bound account/profile creation and ownership-safe mutations.
  Plugin service boundaries now parse external inputs with Zod before side effects.
- **Blogs and editors:** localized publication history supports comparison,
  restoration and collaborative publishing with conflict checks and retained
  images. Blog and Menu editors protect unsaved navigation and ignore stale
  operation completions. Category/label management remains reachable from editors.
- **Reservations and Drive:** Reservations opens in a paginated all-date List,
  shares month navigation with booking forms, batches month availability reads
  and creates staff bookings on a dedicated page. Drive preserves its sidebar
  during folder navigation and keeps submitted recovery/retries coherent across
  view changes. New object names preserve descriptive filename fields.
- **Account and records:** account sections retain drafts and support a separate
  email-change flow. Tables share selection, confirmed bulk deletion and
  failed-only retries. Employee deletion can review linked data, while photos and
  customer creation avatars use consistent presentation. Late optimistic results
  cannot overwrite a different record or client scope.
- **Shared UI and showroom:** reusable image cropping exports WebP; loading
  feedback shares one navbar bar; content/sidebar layouts and sticky table
  actions improve narrow views. The showroom adds keyboard search, category
  colors and a responsive settings sidebar; previews share the main document.
  Mailing examples stay neutral. Native Oxlint rules replace the React Hooks plugin.

## Breaking integration and migrations

### Database cutover

**Schema/data migration is required for existing persistence installations.**
Follow the [persistence guide](../persistence.md), inspect the actual host schema
and preserve its applied migration history. Registry installation runs no migration.

1. Align Drizzle ORM/Kit at `1.0.0-rc.4`, compose installed table exports and
   `pluginLocks` with the host auth schema, and generate reviewed incremental
   migrations. Convert older Kit history through its documented `up` workflow.
   Remove `menusPlugin()` registration and its obsolete installed file. Do not
   replay creation SQL or overwrite existing auth/schema history.
2. Stop all old writers and workers. Add persistent lock rows, Blog projections,
   history structures and retained-image references, plus the Reservations status
   column. Hosts predating named Drive objects also need nullable `storage_name`
   columns; existing NULL names keep their object keys. Row locks do not coordinate
   with the old advisory-lock writers.
3. With writers stopped, run `storage.backfillHistory(tx)` when adopting history,
   then `backfillBlogProjections(tx)` in a reviewed transaction. Verify document,
   publication and retained-image invariants. History cannot recover discarded
   text or unknown authors. See [Blog migration](../blogs.md#history-migration-and-rollback).
4. Await `assertMigrationsApplied` and Blogs `preflight()` before enabling traffic
   or workers. They reject missing/edited migrations and incomplete projections;
   they do not repair data. Start compatible services together after verification.
5. Preserve IDs, credentials, tokens, existing object keys and migration history.
   Rollback requires stopped writers and compatible code retaining additive data;
   old Blog writers can leave projections stale. Production upgrades and historical
   database layouts require host-specific rehearsal beyond the fresh-schema suites.

### Host adapters

- **Customers/Employees/Projects:** customer creation now requires a real unused
  email. Email-less contacts need a separate adoption decision; never invent emails
  or attach existing accounts automatically. New Customers storage requires a
  transaction-bound Better Auth factory and hooks. Creation returns
  `{ customer, invitationSent }`; lost responses or failed delivery recover through
  lookup and `resendInvitation`. Guard customer membership separately from the
  `user` role, exclude customer profiles from employee directories before paging,
  and guard direct auth admin endpoints. Projects retains ownership and legacy
  metadata on ordinary edits. See [Customers](../customers.md),
  [Employees](../employees.md) and [bounded directories](../persistence.md#bounded-customer-and-project-directories).
- **Project forms:** callbacks contain only `name`, `status`, `description`.
  Remove directory props, `defaultOwnerId`, `lockOwner`, obsolete URL labels and
  `safeProjectUrl`. `Project.url` is removed; storage retains the legacy column.
  Supply authorized ownership on create and preserve stored metadata on update.
  See [Project adoption](../projects.md#updating-existing-hosts).
- **Reservations:** expose authenticated
  `listPage({ page, resourceId?, serviceId?, status? }) -> { items, hasMore }`.
  Install UI, storage and transport together. Add the staff creation route and
  `newHref`; wire URL-owned page/calendar state and translated pagination labels.
  Ordinary calendar reads retain the 43-day bound. See [Reservations](../reservations.md).
- **Blogs/Menus/Drive:** update complete items, optional history transport and
  navigation guards together. Custom Blog model callers must replace `saveArticle`
  and `recordBlogSave` with `saveBlogDraft`; `BlogsClient.save` stays unchanged.
  Remove obsolete private editor/recovery files only after checking host imports.
  Keep Drive mounted across folder URLs and reset it on authenticated identity
  changes. Update upload UI alongside its hook (`upload.name` replaces private
  `upload.file.name` access). Preserve server authorization and scoped storage keys.
- **Shared controls/Auth:** custom `useTableSelection` callers must replace retired
  `setPending`, `delete` and `remove` coordination with the documented session API.
  Integrate one loading provider/indicator in the host shell; translate new labels
  and preserve semantic theme tokens, Tailwind scanning and framework shims.
  Email changes require the host's authenticated old/new-address confirmation flow.
  `back-to-top` is no longer distributed; keep any needed existing implementation
  host-owned. See [selection adoption](../table-selection.md#custom-confirmation-adapters-and-adoption),
  [loading feedback](../loading-indicator.md) and [Auth](../intranet-auth.md).

Employee photo bytes belong in private host S3 storage; metadata remains in the
database. Existing byte migration and cleanup are separately reviewed host work.
No deployed objects or customer records are changed by this release.
