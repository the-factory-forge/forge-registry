## Supported baseline and changes

The baseline includes public pages and sections, Auth and employee management,
Customers and Projects, Drive, Blogs, Menus, Reservations, Mailing and their
optional server companions. Hosts own routing, authorization, branding,
translations, persistence composition, transports and deployment. The
[manifest](../../registry/registry.json) defines each item's complete files,
targets and dependency requirements. The legacy Radix tag is not a compatible
installation baseline.

Since RC6:

- **Connectors:** `customers-bexio` and `customers-bexio-server` provide explicit
  contact linking, reviewed imports, saved-customer synchronization and recoverable
  bulk provisioning. The server companion enforces installation-scoped person
  uniqueness. `projects-drive` embeds Drive in a project scope while leaving both
  base plugins independently installable.
- **Blogs:** history distinguishes saved versions from the working draft and
  supports explicit comparison. Draft restoration preserves the editor's dirty-state
  and recovery behavior. The storage companion accepts draft comparison inputs.
- **Auth and accessibility:** credential controls wait for hydration and forms use
  POST. Lightbox hover scaling and transitions respect reduced-motion preferences.
  Employee photo uploads use descriptive WebP filenames. Contextual
  action labels are shorter across Auth, Customers, Employees, Menus, Projects and
  Reservations; hosts with label overrides should review the current contracts.
- **Showroom and maintenance:** social sharing metadata and the preview image are
  present. Provider-owned synchronization and release guidance now use
  `.agents/configs/`; these records do not establish customer adoption.

Directly changed items are `auth`, `blogs`, `blogs-storage`, `customers`,
`customers-bexio`, `customers-bexio-server`, `employees`, `lightbox`, `menus`,
`projects`, `projects-drive` and `reservations`. The three connector items are new;
no item was removed since RC6. Additional reverse dependents are
`customers-storage`, `employees-server`, `intranet-shell`, `intranet-sidebar`,
`menus-storage`, `projects-storage` and `reservations-storage`. Shared-file owners
and dependency closure were compared against both manifests. Existing item
dependencies and the repository lockfile are unchanged since RC6; new connector
dependencies are declared in their manifest entries.

## Integration and migrations

1. **Adopt the RC baseline deliberately.** Earlier installations require the
   [RC4 invitation changes](v0.0.0-rc.4.md#breaking-integration-and-migrations) and
   [RC5 persistence and host-adapter cutover](v0.0.0-rc.5.md#breaking-integration-and-migrations).
   Preserve applied migrations, IDs, credentials, tokens and object keys. Align
   Drizzle ORM/Kit with the selected companion contracts; generate and review
   incremental migrations. Stop old writers before changing lock/projection
   protocols, backfill Blog history/projections as documented, and run migration
   and projection preflights before traffic. Registry installation runs no SQL.
2. **Configure Bexio only when requested.** Follow the
   [connector guide](../customers-bexio.md). Compose its link table with host-owned
   migrations and repair duplicate links before adding uniqueness constraints.
   Supply server credentials, fresh authorization, installation-wide concurrency
   control, transaction-bound identity provisioning and invitation recovery.
   Writes to Bexio and the local database are not one transaction; inspect uncertain
   outcomes before retrying. Existing base plugins need no new schema for this item.
3. **Preserve host boundaries.** Adapt framework shims, labels, theme tokens and
   Tailwind scanning. Supply server authorization independently of disabled UI.
   Project Drive requires an authorized scope resolver on every operation and
   adds no storage schema or automatic folders. Existing storage prefixes and
   deployed objects require their own reviewed adoption plan.
4. **Review current Blog and Auth contracts.** Update complete selected items and
   relevant companions, preserving host callbacks and local fixes. Existing
   installations need no additional schema migration for the post-RC6 Blog,
   Auth, Employee-photo or Lightbox changes.

  its own `@/*` alias. A separate 29-item Template installation and its dependency

  Unpinned dependencies resolved independently, including cnfast 0.2.0,
  Lucide 1.66.0, Motion 14.9.0 and Zod 4.6.7.

  and GitHub release immutability settings were not verified. No live data or

## Adoption and limitations

After publication, verify the tag's full SHA and pin the entire `@forge` namespace
to that immutable source. Install selected items and their dependency closure in
a disposable host first, then review overwrites, aliases, styles and resolved npm
dependencies. A source SHA does not pin unversioned npm requirements.

The [central consumer inventory](https://github.com/the-factory-forge/forge-specs/blob/main/consumers/sites.yaml)
tracks known installations. Existing customer source and deployments are unchanged;
unknown consumers and historical customizations still need review. Customer database
upgrades require host-specific rehearsal. Live Bexio, email, OAuth, hosted storage
and deployment are outside this local release preparation.
