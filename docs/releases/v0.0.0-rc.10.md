# v0.0.0-rc.10 — Editor loading, table sorting and Support priorities

This prerelease covers changes since `v0.0.0-rc.9`
(`de9fc55ea117f81cef330a9965f0e18c16405b9d`). Prepared on 22 November 2026 for
`the-factory-forge/forge-registry`. The annotated tag identifies the exact source
commit. No separately uploaded assets.

## Changes

- **Record screens:** Open Blog posts, Menu items, Customers, Projects and Support
  tickets with a loading title, a status badge and disabled fields. The
  showroom can simulate Blog loading, and the shared loading bar sits behind dialogs.
- **Blogs and Employees:** Blogs has simpler editing, publishing and version history.
  Both plugins share photo pickers and status toggles.
- **Tables and navigation:** Record tables use sortable headers and remember
  ordering. Views remember layout preferences. Back links and action labels
  are simpler, and the default intranet topbar aligns with the sidebar.
- **Support:** Tickets have type badges, description prompts, sortable headers
  and priorities. The GitHub connector supports request-driven delivery. A failed
  first issue creation waits for staff retry.
- **Auth and showroom:** Password recovery prefills the sign-in email. Sign-in
  failures use toasts. The showroom demonstrates shared sorting and fits homepage
  cards on narrow screens.

## Adoption

1. Pin the whole `@forge` namespace to the release commit SHA. Review the selected
   source and its dependencies before overwriting host files. Preserve host aliases,
   translations and theme tokens. Use Node types for server companions.
2. Bind sort state to host URLs where applicable and pass sorting to the server
   before paging. Check reload and Back/Forward. Mount one shared loading provider
   and indicator in the app shell. See [sorting](../plugins.md#table-sorting)
   and [loading feedback](../loading-indicator.md).
3. Before deploying Support storage, generate and review the migration for the
   generated `supports_ticket.author_name` column and nullable `priority` column
   with its P0–P4 check. Existing tickets start with no priority. Apps can opt
   into priority editing through `setPriority`. See [Supports](../supports.md).
4. Update the GitHub connector UI and server together. Use the
   [dedicated App guide](../corner-support.md) for current host setup. Review
   existing bindings before changing credentials. Validate private repository
   access, signed webhook import, first-send retry and reconciliation in
   staging. See [Supports–GitHub](../supports-github.md).
5. Review the central consumer inventory before upgrading a site. No customer
   installation, live migration, credential change or deployment forms part of
   this release. Consumer-specific checks remain open.
