**Use this candidate for evaluation. Review the integration requirements before adopting it.**

Prepared on **11 October 2026** for `the-factory-forge/forge-registry`.

- **Release status:** first semantic release candidate. Any publication must be a prerelease, not “latest.”
- **Browser status:** the tagged candidate has five unresolved assertions. With the follow-up fixes below, all **163 browser tests pass** against the production build.
- **Customer impact:** preparation does not update customer source, migrate data or deploy websites.
- **Publication:** the original commit and tag have been pushed. The follow-up fixes below are separate from that tag and require their own publication authorization.

## What is included

This release distributes **editable source** through shadcn’s `@forge` namespace.
Generated endpoints live in `public/r/`. The [manifest](../../registry/registry.json)
owns the complete file and dependency inventory.

- **Public websites:** `page-faq`, `page-contact`, `page-legal`, heroes, service grids, testimonials and pricing sections.
- **Internal workspaces:** `intranet-sidebar`, `intranet-shell`, `auth`, `employees`, `customers` and `projects`. `employees-server` provides the fresh-session administrator guard; customers and projects use host callbacks.
- **Files and publishing:** `drive` / `drive-storage` provide scoped folders, uploads, ZIP downloads, duplication and optional trash recovery. `blogs` / `blogs-storage` provide multilingual Markdown, publication snapshots, categories and private images.
- **Menus and reservations:** `menus` / `menus-storage` provide restaurant menus, translated labels, sizes, images, ordering and print layouts. `reservations` / `reservations-storage` provide appointments, overnight stays, calendars, signed management links and durable notification jobs.
- **Shared building blocks:** `ui-shims`, `icon-tooltip`, `action-toast`, `optimistic-action`, `editor-form`, `dialog-submit`, table controls, semantic styling and consent analytics. Dependencies install with their parent items.

The showroom uses React 19, TanStack Start/Router, Tailwind 4 and Nitro. Shared UI
uses Base UI and framework shims.

**Hosts supply routing, authentication, labels, themes, transport and business data.**
Showroom versions are recorded in [package.json](../../package.json) and the lockfile;
distributed item dependencies are defined separately in the manifest.

## Before adopting source

**Compatibility with historical customer copies or the legacy Radix tag is not guaranteed.**
Review each selected item’s guide and source diff.

1. **Prepare the host UI.** Supply semantic colors, status pairs, layout utilities and fonts. The showroom stylesheet does not install automatically. Adapt `ui-shims` to the host framework and keep adapters outside registry-managed paths.
2. **Enforce authorization on the server.** Employee routes, reads and mutations require fresh-session administrator authorization. Supply `currentUserRole` to employee UI. Other plugin callbacks also need server-side authorization and validation.
3. **Check object-storage prefixes.** Drive requires `<SITE_NAME>/drive/`; Blogs requires `<SITE_NAME>/blogs/`. Menu images use Drive’s scope. Existing unscoped objects need a separately reviewed copy, database-key update and verification before cleanup. **Installing source moves no objects.** Read the [Drive](../drive.md), [Blogs](../blogs.md) and [Menus](../menus.md) guides.
4. **Review SQL through the host migration workflow.** Menus includes incremental spice-level, size and label-icon migrations. Do not rerun initial creation SQL on existing databases or apply both shipped and generated DDL. For Reservations, review its [schema, notification worker and `deriveManagementSecret` setup](../reservations.md). **Changing the management secret invalidates existing links.**
5. **Preserve customer fields when replacing adapters.** Blog text editing works without S3; uploads report `STORAGE_NOT_CONFIGURED`. Preserve custom article data. Project forms edit only name, status and description; host updates must preserve customer ownership and other omitted fields.

Release metadata and the browser fixes introduce no schema or data migration. The included source has
the setup requirements above; none were applied to customer systems during preparation.

## Validation and post-tag corrections

**Registry, unit, browser and production checks were rerun for the follow-up fixes.**
Storage and fresh-consumer results below come from the original candidate validation;
those suites were not rerun for these CSS and test corrections.

### Passed checks

- **Documentation amendments:** formatting, link review and `git diff --check`.
- **Registry and code:** `pnpm format`, `pnpm lint:fix`, `pnpm registry:sync`, `pnpm registry:check`, `pnpm typecheck` and `pnpm check` passed. Rebuilt `drive` and `menus` endpoints match their source. The combined check reported **zero errors and 194 existing lint warnings**, including accessibility and unhandled-promise warnings.
- **Tests and production build:** all **81 unit tests**, `pnpm build` and the deployment smoke test against the local production server passed. Build warnings included bundled `use client` directives and chunk sizing.
- **Storage:** Drive, Blogs, Menus and Reservations integration suites passed against disposable PostgreSQL/MinIO services. Drive and Blogs restart-persistence checks passed. Drive’s browser fixture shares port `19040` with Blogs’ MinIO; Drive passed on rerun after Blogs stopped.
- **Consumer installation:** every manifest item installed through the pinned shadcn CLI into a fresh consumer and passed strict TypeScript validation. The consumer used ES2023 libraries, Node/React types and host CSS declarations, with no showroom aliases.

**A source SHA does not pin npm packages.** During consumer installation, some
unpinned dependencies resolved beyond showroom versions: AWS SDK `3.1149.0`,
cnfast `0.2.0`, Motion `14.1.0` and Zod `4.6.5`.

### Browser fixes and verification

The original run had 156 passes and seven failures across 163 tests. The two
reservation tests already use selectors matching the grouped timezone UI. This
follow-up fixes the remaining five failures:

- Drive's plain breadcrumb title now has the same responsive minimum height as
  its rename control, removing the 4px loading-to-ready table shift.
- Menu preview and print documents override the host's `:root` scrollbar gutter
  at matching specificity, restoring the 210mm paper width while retaining the
  responsive preview.
- Print recovery waits for the shared save toast instead of the removed status.
- The menu-size test consumes the creation toast before saving visibility, so
  an earlier confirmation cannot satisfy a later save wait.
- The showroom test checks unique, nonempty metadata and matching Open Graph
  values without requiring every title or description to contain fixed words.

All **163 browser tests pass**, with no failures or skips, against the local
production build using `TEST_BASE_URL` and `node --test --test-concurrency=2 tests/*.browser.mjs`.
All five focused regressions also pass. Desktop/mobile captures show no overflow,
and Drive loading checks cover both themes and viewport sizes. An earlier
development-server run was stopped after additional timeouts; the complete
production run above is the final browser result.

These corrections are **not included in the pushed `v0.0.0-rc.1` tag**, which
still resolves to `5ce2a53c1024a4df5f4ee53f03cc8fc5d824702b`. They are recorded in a
separate fix commit; the tag's original browser limitations remain applicable.

## Adoption after publication

1. **Verify the release tag’s full commit SHA.** Pin the entire `@forge` namespace to:

   ```text
   https://raw.githubusercontent.com/the-factory-forge/forge-registry/<full-sha>/public/r/{name}.json
   ```

2. **Install only the selected items** with `shadcn add @forge/<item>`. Review source changes and external dependency changes.
3. **Validate the host before deployment.** Check themes, routing, permissions, translations, failure recovery and affected user journeys.

The consumer test verifies installation and types. It does **not** certify customer
adapters or visual integration. Remote assets, live authentication/email, analytics
and customer migrations were not exercised.

The CSS corrections ship in `drive` and `menus`, also reached through
`drive-storage` and `menus-storage`. The recorded consumer Terminal60 was inspected
at `0ee0abfb1d73e3b0debcc9c30dab81e15e71223e`: its older Drive lacks inline title
renaming and its Menus copy has no printer, so these fixes do not require an
immediate change there. The template installs neither plugin. Unrecorded consumer
usage remains unknown; customer sources and deployments were not changed.
