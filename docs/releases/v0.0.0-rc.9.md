# v0.0.0-rc.9 — Support, external assistants and composed menus

Support requests can now be stored privately and delivered to GitHub. This RC also
includes every registry change since RC8: external assistant operations, model
connections, reusable menu composition and shared UI improvements.

Prepared on 15 November 2026 for `the-factory-forge/forge-registry`. Previous release:
`v0.0.0-rc.8` at `5ffb422ce0034a77837d76e0035567a0f3d38968`. Resolve the annotated
`v0.0.0-rc.9` tag for the final full source SHA. This is a prerelease, never latest,
with no separately uploaded assets.

## Changes

- **Support:** shared staff tickets, safe Markdown, private image attachments,
  retry-safe persistence, and a GitHub connector with transactional delivery,
  signed reply/status import, reconciliation and operator recovery.
- **Agents:** administrator-managed encrypted model connections and an optional
  MCP server for external assistants. Business writes retain durable proposals,
  fresh authorization and recovery. Installing source does not grant an assistant access.
- **Menus:** reusable menus and shared categories, unassigned dishes, translated
  content, weekly menus, private previews, photo presentation and Web/Paper printing.
  Existing flat integrations remain supported.
- **Shared UI:** collection navigation in Lightbox, Drive refresh, section anchors,
  email copy controls, submit shortcuts, missing-avatar fallback, toast pointer
  handling and a cookie banner with two compact actions and explicit custom selection.

## Required adoption steps

1. Pin the entire `@forge` namespace to the verified release SHA. Install selected
   items and dependencies in a disposable host before reviewing source overwrites.
   `cn` replaces `cnfast`; preserve host aliases. The MCP companion adds
   `@modelcontextprotocol/server`, and Support declares `@tanstack/markdown`, Zod
   and its storage packages. Hosts need current Node/React tooling and ES2023 or
   newer TypeScript libraries for existing Drive/Menu array APIs.
2. Remove the obsolete CookieBanner `closeLabel` prop. The banner has no close
   action: **Custom selection** and **Accept all** are its compact actions.
   Hosts provide translations and connect consent to analytics.
3. Generate and review forward migrations for selected persistence companions.
   Support adds ticket/activity/attachment/idempotency tables; GitHub adds binding,
   delivery, job and message tables. Agents adds encrypted model settings and
   external proposal identity (`source` defaults to `chat`); custom stores must
   implement insert-only `create`. Menus adds cards/sections, category versions and
   descriptions, nullable dish price/category fields, and menu type/week/currency
   fields. Remove the old category `NOT NULL` constraint while preserving dishes.
   Registry installation applies no SQL and does not rewrite migration history.
4. Supply fresh staff authorization, authenticated transport and private scoped S3
   storage. GitHub delivery requires a private repository, scoped App credentials,
   raw signed webhook handling, delivery/reconciliation/cleanup jobs and monitoring.
   Model connections need a stable server-only encryption key. MCP requires host
   OAuth/grant checks; returned information is processed by the assistant provider.
5. Follow [Support](../supports.md), [GitHub delivery](../supports-github.md),
   [Agents](../agents.md) and [Menus](../menus.md) for integration and recovery.
   Review the central consumer inventory before customer adoption. This release
   changes no customer checkout, credentials, database or deployment; uninspected
   consumers remain follow-up work.
