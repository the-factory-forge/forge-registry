# v0.0.0-rc.6 - readable Blog previews and grouped Mailing examples

**Update `blogs` with its layout dependency to keep history readable in narrow
containers.** Mailing gains grouped showroom examples and a site preview guide.

Prepared on **28 October 2026** for `the-factory-forge/forge-registry`.
This is an evaluation candidate. Any future GitHub Release must be a prerelease,
not latest.

## Changes and affected items

- **`blogs` and `content-sidebar-layout`:** history and editor fields now adapt
  to their container width. Small and Medium showroom previews keep readable
  fields and preserve unsaved edits. The sidebar stacks above content below
  64rem of available layout width; wider containers retain the 22rem sticky panel.
  Root `className` sizing continues to work inside flex rows. See
  [the layout guide](../content-sidebar-layout.md) and
  [PR #35](https://github.com/the-factory-forge/forge-registry/pull/35).
- **Mailing showroom:** ten account and reservation examples use The Corner
  Factory identity, with independently collapsible Account and Reservations
  groups. Direct links, HTML/plain-text selection and Back/Forward preserve the
  selected sample and keyboard focus. The [Mailing guide](../mailing.md) explains
  host-owned email editing, local previews and logo requirements. The distributed
  `mailing` renderer and customer brand adapters are unchanged. See
  [PR #34](https://github.com/the-factory-forge/forge-registry/pull/34).

The changed distributed items are `blogs` and `content-sidebar-layout`.
`blogs-storage` depends on `blogs` and therefore also reaches the changed layout;
its server source is unchanged. No items were added or removed. The registry
manifest, npm dependencies and lockfile are unchanged relative to RC5.

## Compatibility and migrations

**Schema and data migrations: none relative to RC5.** No public props, callbacks,
storage keys, authentication rules or email transports change.

Hosts must scan installed source with Tailwind CSS 4 so the named container-query
utilities are generated. Give the layout a resolved width in intrinsic `w-fit`
compositions. Preserve existing header offsets, framework shims and theme tokens.
The Mailing showroom identity stays local to the showroom; consumers still own
their email branding and delivery.

## Validation

- **Registry and code:** the official shadcn builder reproduced committed output.
  Registry JSON parsing, TypeScript and the combined formatting/lint/type check
  passed with no lint warnings or errors. All 130 unit tests passed.
- **Production and browsers:** the production build and all 48 selected browser
  and smoke tests passed. Coverage includes Blog history and draft retention,
  sidebar stacking, flex sizing, both themes, narrow previews, Mailing navigation
  and the production asset/registry endpoints. Bundled `use client` directive
  warnings remain in the production build.
- **Disposable consumer:** shadcn 4.22.1 installed `blogs`,
  `content-sidebar-layout` and their dependencies into an empty source tree with
  a reused dependency cache. Strict TypeScript and a production build passed using
  only the consumer's `@/*` alias. Browser assertions passed in both themes for
  wide/narrow layout, flex sizing, draft retention across panel toggles and 390px
  overflow. The host used Tailwind CSS 4 without showroom CSS. Its build reported
  the usual large-chunk warning. Unpinned dependencies resolved independently of
  showroom pins, including cnfast 0.2.0 and Lucide 1.61.0.
- **Omitted:** the complete browser suite, storage integration suites, live email,
  hosted providers and customer deployments. No server companion changed in this
  candidate; showroom examples do not send mail. Existing RC5 persistence cutover
  requirements remain in [the RC5 notes](v0.0.0-rc.5.md).
